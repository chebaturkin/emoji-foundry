# High-definition TGS emoji design

## Причина изменения

Видео custom emoji Telegram обязаны иметь размер 100 x 100 px и частоту не выше 30 FPS. Официальный лимит видео emoji равен 256 KiB. Прежнее ограничение WebM до 64 KiB было ошибочным переносом лимита TGS на видео и необоснованно ухудшало качество пяти сложных файлов `08`, `18`, `19`, `22` и `23`.

Визуально более четкие анимированные emoji используют TGS. Telegram описывает TGS как векторный Lottie-формат для высокодетальных анимаций. Его холст имеет размер 512 x 512 px, частота составляет 60 FPS, а файл не превышает 64 KiB.

## Решение

Основным качественным результатом становится отдельный TGS-пак из 27 emoji. Существующий WebM-пак сохраняется как резервный совместимый вариант и кодируется не тяжелее 256 KiB. Все текущие WebM укладываются в этот лимит в lossless-режиме.

TGS строится не из декодированного WebM и не из сохраненных кадров 100 x 100. Каждый `FrameMotionSpec` сначала рисуется в 400 x 400, проходит тот же safe-area монтаж, затем переводится в векторные контуры на холсте 512 x 512. Контуры используют только утвержденную палитру. Растровые изображения, текстовые слои, маски, эффекты и другие запрещенные TGS-функции не применяются.

Каждый исходный кадр 30 FPS представлен в TGS двумя кадрами на timeline 60 FPS. Формы остаются настоящими Lottie paths, поэтому Telegram масштабирует их без растровой пикселизации.

Для распознавания файла загрузчиком Telegram документ содержит официальный верхнеуровневый маркер `"tgs": 1`, который добавляет Bodymovin-TG. Без него мини-приложение сообщает, что формат файла не поддерживается. Для совместимости с Telegram `rlottie` каждый набор path и fill вложен в Lottie shape group, который завершается обязательным group transform. Самый выразительный непрозрачный кадр переносится в начало цикла TGS и WebM. Благодаря этому Telegram получает корректную миниатюру и не показывает пустую серую ячейку.

## Компоненты

- `tgs_core/vectorize.py`: перевод RGBA-кадра в упрощенные замкнутые контуры утвержденных цветов
- `tgs_core/build.py`: создание минимального Lottie JSON и детерминированного gzip TGS
- `build_tgs.py`: сборка одного stem, группы или полного пака
- `validate_tgs.py`: проверка 512 x 512, 60 FPS, длительности, типов слоев, отсутствия растров и лимита 65536 байт
- `tgs_upload`: готовые файлы для загрузки

## Quality gates

- ровно 27 TGS
- холст 512 x 512
- 60 FPS
- длительность совпадает с WebM
- не больше 65536 байт
- верхнеуровневый маркер `tgs` равен `1`
- только shape layers и fills из фирменной палитры
- первый кадр содержит видимую форму для миниатюры Telegram
- каждый shape group завершается transform и проходит проверку совместимости структуры
- резервный WebM не больше 262144 байт и имеет видимый первый кадр
- все текущие Python-тесты и валидаторы проходят
